# Library, Search, Cover Editor, and Batch

Run `python qt_gui.py` for the PySide6 desktop app. The original Tkinter program remains available with `python gui.py`; the CLI remains in `steamcase.py`. The desktop app has Library, Search, Batch, Backup and Settings in its navigation rail. Library and Search share one Cover Editor on the right; Batch, Backup and Settings use the full content width. In Library, drag the horizontal divider between the game list and Cover Artwork to give either area more height; its position is saved as a nonsecret preference. The artwork grid scrolls vertically, while the current and new covers remain visible in the editor.

## Choose and edit

- **Library** loads installed Steam games from the main and additional `steamapps` folders in `libraryfolders.vdf`, plus shortcuts from the selected account's `shortcuts.vdf`. To include games that are not installed, use **Download your game list** to open Steam's userdata page, save it as `userdata.json`, then use **Load userdata.json**. The app remembers the last valid path. The JSON contains app IDs but does not identify the selected local Steam account, so use a file downloaded while signed in to the intended account. The Library shows imported IDs only when Steam's catalog provides a game title; unknown IDs and non-game entries are omitted from game counts. **Local only** clears the saved import and shows installed games and shortcuts. If the file is later missing or unreadable, installed games still load. Search filters as you type; All, Installed, Not installed and Non-Steam show counts for the matching titles. Each game occupies one row, and hovering shows its full title and ID. Selecting a Steam game loads its exact artwork ID, current custom cover (or Steam CDN portrait), and Steam CDN artwork. An existing shortcut must be matched to a SteamGridDB result explicitly, or given a local image; its verified shortcut ID is retained. The app reads but never changes Steam library files.
- **Search** works without Steam. Search Steam CDN or SteamGridDB by name and choose the exact game result. The app never accepts a fuzzy title automatically. SteamGridDB name results show their IDs; its portrait results appear in the same cached, asynchronously populated thumbnail grid used by Library. Click anywhere on a thumbnail card to select it; arrow keys move through the grid and Enter adds the selected, rendered cover to Batch. Technical artwork IDs appear in tooltips. Use **Import local PNG / JPG / WebP** for an image on disk.
- **Cover Editor** has the 29 platform choices, an image-source selector, a current Steam portrait and a large final 600 × 900 framed preview. Choose an artwork thumbnail or local file; changing the platform renders the same image again with that frame. Tick **Platinum Edition** to add a subtle silver-blue rim around the entire cover and one trophy at the bottom. It is off by default and saved separately for each selected game, including Steam and non-Steam games. Switching artwork or platform keeps the choice. Game title graphics remain part of the selected artwork, with no separate logo control. Steam games default to Steam CDN, other games to SteamGridDB. A selected Steam game may use any platform frame. [Compare normal and Platinum previews](platinum-comparison.png).

## Apply, export, recover

**Apply to Steam** in the editor applies one selected verified Steam game or shortcut directly; Batch is optional. **Export PNG** writes one cover to the configured folder, including without Steam. **Add to batch** queues an edit under its verified Steam ID or a local key; adding another edit for the same game replaces its queued version. Batch shows the title, cover thumbnail, platform, Platinum state and status. Double-click or **Edit selected** to revise an item, **Remove** to discard it, **Export all PNGs** for local copies, or **Apply all to Steam** for the verified entries. Local-only items stay in the queue for export. Platinum is a manual label; no achievement API is queried.

**Generate all covers** in Batch retains the automatic Steam renderer, optionally skipping blurry source art. Its completed covers join the same Batch queue. You can cancel generation; completed files remain available. A manually edited cover already queued for a game takes precedence. Each game's manually selected platform is saved as a nonsecret preference; the image and preview currently being edited stay temporary.

Before any Apply, all selected covers are rendered and IDs checked. Shortcut IDs are read again from `shortcuts.vdf`. If Steam is running, the app warns you and stops it once, calls the existing atomic backup/apply code once, and optionally starts Steam once after the batch. A failed preparation never closes Steam. A write failure invokes the existing rollback; the Batch status shows the error and remains editable. **Backup → Restore previous artwork** restores the latest backup. **Reset to Steam default** removes this app's custom covers with a backup; selecting **Reset all custom portraits** additionally removes art set manually or by another tool. The app does not offer a live apply mode: it cannot guarantee when Steam will reload custom artwork from its cache, as illustrated by [Valve's client issue tracker](https://github.com/ValveSoftware/steam-for-linux/issues/8908). Even after restart, the client may briefly show a cached cover.

## Settings and network behavior

Settings holds the Steam account, default export folder, default artwork source, restart preference, and SteamGridDB key management. **Check and save** validates a newly entered key before writing it through `keyring` to the operating system credential store. **Verify stored** tests it without displaying it; **Delete** removes it. The key is never written to settings JSON or logs. The [SteamGridDB API](https://www.steamgriddb.com/api/v2) supports game search and portrait grids; results are cached for one day, grid listings for six hours, and downloaded images by URL. HTTPS, download-size bounds, and image validation come from `cover_workflow.py`. Authentication, rate limits (including `Retry-After`), network and image errors appear in the app without blocking the UI.

### Backup view

Choose the Steam account in Settings, then open **Backup**. **Export current artwork** creates a new folder with `manifest.json` and the original `<artwork-id>p.png`, `.jpg`, `.jpeg` or `.webp` files from that account's `config/grid`. It includes locally set portraits for Steam games and non-Steam shortcuts, regardless of which tool created them. Invalid, linked or missing files are reported as skipped. Steam's CDN defaults have no local portrait file and are never counted as exported.

**Import artwork backup** opens one of these folders and previews its files, IDs, image, missing/invalid entries, overwrites and format conflicts. Import is blocked for damaged or incomplete backups. After confirmation, the app validates the files again, closes Steam once if needed, backs up every affected current portrait into the account's normal restore history, then writes the original filenames atomically. If a write fails, it rolls back the changes. The import summary includes the safety-backup path; **Backup → Restore previous artwork** can undo a completed import. Importing into a different selected account requires explicit confirmation. Steam may briefly show cached artwork after restart.

`qt_gui.py` owns Qt views and worker dispatch, and only updates widgets in the GUI thread. `case_service.py` composes the existing `steamcase.py` and `cover_workflow.py` backend calls for direct and batch actions; it does not implement another Steam writer, renderer, downloader or credential store. `steamcase.spec` packages the Qt entry point as `CaseCovers`; `steamcase-tk.spec` keeps a build recipe for the fallback. See [README](../README.md), [frame architecture](stages-1-to-3.md), and [third-party asset provenance](../THIRD_PARTY.md).

On Windows, `tools/build_windows.ps1` runs PyInstaller with a clean native-library search path after `requirements-build.txt` is installed in `.venv`. This prevents unrelated developer tools on `PATH` from contributing DLLs to the standalone EXE.

## Crash diagnostics

The Qt app writes Python exceptions, background-job tracebacks, and Qt warnings to `%LOCALAPPDATA%\Case Covers\logs\case-covers.log` on Windows. `native-crash.log` in the same folder receives `faulthandler` thread stacks for native access violations when Python can capture them. These logs work in the packaged windowed EXE, which has no console. On other systems they live in `~/.local/state/case-covers/`. Set `CASE_COVERS_LOG_DIR` to use another location. The logs contain no API key or Python local-variable dumps.

For a repeatable GUI stress exercise, `python qt_gui.py --diagnose-batch-grid --diagnose-batch-race` creates temporary artwork and adds 60 covers, edits 50, and removes 50. The same arguments work with `CaseCovers.exe`; no Steam files or network services are touched.
