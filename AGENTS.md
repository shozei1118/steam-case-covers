# Case Covers project rules

- The primary desktop UI is `qt_gui.py` (PySide6): Library, Search, Batch, Backup, Settings in a left navigation rail. Library and Search share one right Cover Editor; Batch, Backup and Settings use the full content width. Backup exports and imports locally stored Steam grid portraits through `steamcase.py`; it never claims Steam CDN defaults are local files. Preserve `gui.py` as a working Tkinter fallback with its original three-step Steam batch workflow, and preserve all CLI commands. Steam remains optional for local export.
- The 29 supported platforms and 600 × 900 transparent frames are defined in `platforms/catalog.json` and `assets/frames/`. Do not change accepted frame geometry, logos, Steam typography, or colors for unrelated work. The Steam header has no Windows/Linux badges.
- `steamcase.py` owns Steam discovery, rendering, apply, portable artwork export/import, backup and restore. `platform_catalog.py` is data-only. `cover_workflow.py` owns source search, cached artwork, credential access and platform export. `case_service.py` composes these backends for both single and bulk workflows; it owns only nonsecret preferences and a queue. `qt_gui.py` runs blocking work in `QThreadPool`; Qt widgets are changed only on the GUI thread. `gui.py` retains its own legacy coordination. Single and bulk Apply use `cover_workflow.export_one` as needed and one `steamcase.apply_covers` call with verified IDs.
- Steam artwork defaults to Steam CDN; other platforms default to SteamGridDB. Never silently choose a fuzzy game or artwork match. API keys belong only in the OS credential store; do not log or save them in plaintext. Network downloads must use HTTPS, size bounds and image validation.
- Applying art to Steam must keep backup/restore behavior. Use only existing, verified shortcut IDs read from `shortcuts.vdf`; do not modify Steam's shortcut records. Background Windows subprocesses must not flash consoles; CLI output remains visible.
- Platinum Edition is a per-game, optional overlay rendered by `platinum_frame.py` through `cover_workflow.py`; it is not a platform. Keep the normal path pixel-identical, the platform logo and art window untouched, and the single trophy within the bottom lip. Preview, Batch, export, Apply, and reset recognition must agree on the selected mode.
- Read `README.md` for user workflows (keep it in the Shozei Game Tracker README style: centered header, badges, emoji feature table, short sections; long help, CLI reference and FAQ go in `docs/DETAILS.md`), `docs/stages-1-to-3.md` for frame architecture, `docs/manual-workflow.md` for search/export, and `THIRD_PARTY.md` for asset provenance. Run `python -m unittest discover -s tests`, `python qt_gui.py --selftest`, and `python gui.py --selftest` after behavior changes. `steamcase.spec` builds Qt; `steamcase-tk.spec` builds the fallback.
- Releases: development stays in `C:\Projects\Case Covers`; GitHub Releases are the only distribution channel, and nothing is copied to any other local drive or folder. Pushing a `vX.Y.Z` tag runs `.github/workflows/release.yml`, which builds, selftests and publishes the Windows EXE, the Windows installer (`CaseCovers-Setup-windows.exe`, after a silent install/selftest/uninstall smoke test), and the macOS and Linux builds. Local Windows builds use `tools\build_windows.ps1 [-Installer]` and `tools\casecovers.iss` (Inno Setup 6); the EXE stays at `dist\CaseCovers.exe` and a verified installer at `build\installer\`. The build derives its version from the latest valid release tag unless `assets/version.txt` is stamped by the release workflow, so tag a new version before building a release with new features. Preserve working app features and user data on every release; installer updates and uninstalls must leave settings and OS-stored credentials intact.
